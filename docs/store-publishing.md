# Chrome Web Store 公開手順

公開に向けた手順と、ダッシュボードに入力する掲載情報のドラフト。

## 前提知識: 拡張IDとOAuthクライアントの関係

- 現在の開発版は `manifest.json` の `key` でIDを固定しており、OAuthクライアントIDはこの拡張IDに紐づいている
- **Storeへの新規アイテムの初回アップロードでは、manifestに `key` を含められない**（エラーになる）。Storeが新しいID・鍵ペアを発行するため、**Store版は開発版と別のIDになる**
- 初回アップロード後にStoreの公開鍵を `manifest.json` の `key` に取り込めば、以降はローカル開発版とStore版のIDを一致させられる（2回目以降のアップロードは `key` を含めてよい）
- IDが変わるため、**GCPのOAuthクライアント側の更新が必須**

## 公開手順（初回）

1. **開発者アカウント**: [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole) で開発者登録（登録料 $5、Googleアカウントが必要）
2. **パッケージ作成**: `npm run package` を実行（`dist/gws-tweaks-v0.1.0.zip` が `key` なしで作られる）
3. **初回アップロード**: ダッシュボードで「新しいアイテム」→ zipをアップロード（この時点では公開しない）。アイテムIDが確定する
4. **公開鍵の取り込み**: アイテムの「パッケージ」タブ →「公開鍵を表示」→ `-----BEGIN/END PUBLIC KEY-----` の間を1行にして `manifest.json` の `key` に設定する。以降、ローカル開発版もStore版と同じIDになる（旧開発ID `mimdhjcmdkjcocbhhddbbgcigkphkhah` と `extension-key.pem` は不要になる）
5. **OAuthクライアントの更新**: GCPコンソール → 認証情報 → 既存の「Chrome拡張機能」タイプのOAuthクライアントの**アイテムID**を新しい拡張IDに更新する（新規クライアントを作った場合は `manifest.json` の `oauth2.client_id` も差し替え）
6. **OAuth同意画面の確認**: 下記「OAuthスコープと審査」を参照
7. **再パッケージ・再アップロード**: `npm run package -- --keep-key` で作り直したzipを同じアイテムにアップロード
8. **掲載情報の入力**: 下記ドラフトを「ストアの掲載情報」「プライバシー」タブに入力。スクリーンショット（1280x800）を最低1枚添付
9. **公開範囲を選んで審査に提出**: まずは「限定公開」（リンクを知っている人のみ）を推奨。問題なければ後から「公開」に変更できる

## OAuthスコープと審査

利用スコープ:

- `https://www.googleapis.com/auth/documents` — **機微（sensitive）スコープ**
- `https://www.googleapis.com/auth/drive.metadata.readonly` — **制限付き（restricted）スコープ**

注意点:

- OAuth同意画面が「テスト」モードのままだと、テストユーザーに登録したアカウントしか認証できない（Store公開しても他ユーザーは使えない）
- 「本番」に切り替えて未検証のままだと、認証時に「確認されていないアプリ」警告が出る（上限100ユーザー）
- 警告なしで広く公開するにはGoogleのOAuth検証が必要。制限付きスコープ（drive.metadata.readonly）は通常CASAセキュリティ評価も要るが、**取得データを端末外へ送信しない拡張機能は評価免除を申請できる**（本拡張はこの方針で実装している）
- 個人利用＋知人程度なら「本番＋未検証（警告あり）」または「テストモード＋テストユーザー登録」で十分

## ストア掲載情報ドラフト

- **名前**: GWS Tweaks
- **概要**（132文字以内）:
  > Google ドキュメント・スプレッドシート・スライドに便利機能を追加。フォルダーパスの表示、Cmd+Vでマークダウン貼り付け、フォント・行間・インデントなど初期設定のワンクリック適用。
- **カテゴリ**: 仕事効率化（ツール）
- **言語**: 日本語
- **詳細説明**:

  ```
  Google Workspace（ドキュメント・スプレッドシート・スライド）にちょっとした便利機能を追加するChrome拡張機能です。各機能は設定画面から個別にON/OFFできます。

  ◆ フォルダーパスの表示（ドキュメント・スプレッドシート・スライド）
  メニューバーの下に、開いているファイルが置かれているドライブのフォルダー階層をパンくずリストとして表示します。クリックでそのフォルダーをGoogle Driveで開けます。共有ドライブにも対応。

  ◆ Cmd+V（Ctrl+V）でマークダウンから貼り付け（ドキュメント）
  通常の貼り付けを、編集メニューの「マークダウンから貼り付け」の挙動に変更します。Markdownテキストが見出し・リスト・リンクに変換された状態で貼り付けられます。右クリックや編集メニューからの貼り付けは通常のままです。

  ◆ ドキュメント初期設定のワンクリック適用（ドキュメント）
  タイトル横の魔法の杖アイコンから、あらかじめ設定したフォント・フォントサイズ・行間・箇条書きインデント幅・ページ分けなしをまとめて適用します。新規ドキュメント作成のたびの手動設定が不要になります。

  ※ フォルダー階層の取得・書式適用にはGoogleアカウントでの認証（Drive・Docs API）が必要です。取得したデータを外部サーバーへ送信することはありません。
  ```

- **スクリーンショット**（1280x800、最低1枚）: パンくず表示中のドキュメント画面、設定画面など

## プライバシータブの申告ドラフト

- **単一用途の説明**:
  > Google Workspaceの編集画面に、フォルダー階層の表示・マークダウン貼り付けのショートカット化・書式初期設定のワンクリック適用という補助機能を追加する。
- **権限の正当化**:
  - `storage` — 機能のON/OFFと書式設定値の保存
  - `identity` — Drive API・Docs APIを呼び出すためのGoogleアカウント認証（OAuth）
  - `host_permissions (googleapis.com / docs.googleapis.com)` — フォルダー階層の取得（Drive API）と書式適用（Docs API）の呼び出し
  - `content_scripts (docs.google.com)` — パンくずリスト・適用ボタンのUI追加とキーボードショートカットの制御
- **リモートコードの使用**: 使用しない
- **データ使用**: ユーザーデータの収集なし（取得したファイル情報・文書構造は端末内でのみ使用し、外部へ送信しない）。「データを販売しない」「承認された用途以外に使用・譲渡しない」の各遵守事項に同意する

## 更新時の手順（2回目以降）

1. `manifest.json` の `version` を上げる
2. `npm test -- --run` で全テストが通ることを確認
3. `npm run package -- --keep-key`
4. ダッシュボードで「新しいパッケージをアップロード」→ 審査に提出
